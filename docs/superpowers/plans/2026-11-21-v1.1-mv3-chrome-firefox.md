# Metis 1.1 (MV3, Chrome + Firefox) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the Metis weather popup as one Manifest V3 extension that runs on current Chrome/Chromium and Firefox, with Vue 3 + Vite, GitHub Actions CI and an automatic release on master.

**Architecture:** Popup-only extension (no background script). The popup shows the last cached result from `localStorage`, then asks `navigator.geolocation` for a position and calls the Eris API; if location fails it calls the IP endpoint. Data logic lives in plain JS modules (`weather.js`, `icons.js`) tested with Vitest; `App.vue` only renders.

**Tech Stack:** Node 24, Vue 3.5, Vite 8 + `@vitejs/plugin-vue`, Vitest + `@vue/test-utils` + jsdom, ESLint 10 flat config + `eslint-plugin-vue`, Prettier 3, `web-ext` 10, `@fontsource/raleway`, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-21-v1.1-mv3-chrome-firefox-design.md`

## Global Constraints

- Branch `v1.1`. Small commits, one per logical change. Never push.
- `manifest_version: 3`; `permissions: ["geolocation"]` only; no `host_permissions`, no `background`.
- API base: `https://weather-api.madadipouya.com/v1/weather`; endpoints `/current?lat=..&lon=..` and `/currentbyip`. HTTPS only.
- No remote CSS/fonts/scripts at runtime. Weather Icons and Raleway are bundled.
- Name shown to users: `Metis Weather`. Version starts at `1.1.0`; tags have no `v` (`1.1.0`).
- Firefox: `browser_specific_settings.gecko.id = "metis-weather@madadipouya.com"`, `data_collection_permissions.required = ["locationInfo"]`, `strict_min_version: "140.0"`.
- Release (user decision, overrides the spec's "bump by hand"): on every push to master the pipeline releases; if the tag for the current `package.json` version already exists it bumps patch, commits `Release v<version>` and pushes that commit, then tags and releases.
- Popup keeps today's look: per-condition photo background, translucent boxes, ~360×380.

## Review Focus

1. Unknown/missing icon code from the API (`iconName` not in the map) → popup still renders with a fallback icon/colour, no crash. Test in Task 2.
2. API answers HTTP 500, or 200 with a non-empty `errors` array → treated as failure; cached data stays visible with "couldn't refresh". Tests in Task 2 and Task 3.
3. Location denied or never answers → IP endpoint used after the timeout (10 s). Test in Task 2.
4. Corrupt `localStorage` entry (bad JSON) → ignored as if empty. Test in Task 2.
5. Offline with no cache → error state with a Retry button that re-runs the fetch. Test in Task 3.

### Task 2: Weather data modules (fetch with IP fallback, cache, icon map)

**Files:**
- Create: `src/popup/weather.js`, `src/popup/icons.js`
- Test: `tests/weather.test.js`, `tests/icons.test.js`

**Interfaces:**
- Produces (`weather.js`):
  - `API_BASE = 'https://weather-api.madadipouya.com/v1/weather'`
  - `getPosition(geolocation, timeoutMs = 10000): Promise<{lat:number, lon:number}>` — rejects on error, missing geolocation, or timeout (own timer as well as the `timeout` option, since some browsers never call back when the prompt is dismissed). Options: `{ timeout: timeoutMs, maximumAge: 600000 }`.
  - `fetchWeather({ geolocation = navigator.geolocation, fetchFn = fetch, timeoutMs } = {}): Promise<{ data: object, source: 'location' | 'ip' }>` — position → `/current?lat&lon`; any `getPosition` rejection → `/currentbyip`. Throws `Error` if `!response.ok` or `data.errors?.length`.
  - `toView(data, fetchedAt: Date)` → `{ place: "<name>, <country>", temperature, feelsLike, max, min` (all `Math.round`), `humidity, wind, cloudiness, pressure, visibility, iconCode: data.iconName, date: fetchedAt.toLocaleDateString(undefined, {weekday:'short', month:'short', day:'numeric', year:'numeric'}), time: fetchedAt.toLocaleTimeString(undefined, {hour:'2-digit', minute:'2-digit'}) }`. Field sources as in today's `App.vue` (`main.temp`, `feelsLike`, `main.temp_max`, `main.temp_min`, `main.humidity`, `wind.speed`, `clouds.all`, `main.pressure`, `visibility`).
  - `CACHE_KEY = 'weatherCondition'`; `loadCached(storage = localStorage): { data, fetchedAt: Date } | null` (null on missing or unparsable); `saveCached(data, fetchedAt: Date, storage = localStorage): void`.
- Produces (`icons.js`): `iconFor(code: string): { icon: string, color: string, image: string | null }` — the 18-entry table from today's `App.vue` (`01d` → `wi-day-sunny`/`#244375` …), `image: \`/images/${icon}.jpg\` (root-relative: the popup HTML may sit in a subfolder of dist)`; unknown code → `{ icon: 'wi-na', color: '#244375', image: null }`.

### Task 4: Packaging, CI and automatic release

**Files:**
- Create: `.github/workflows/ci.yml`, `.github/workflows/release.yml`, `.github/dependabot.yml`
- Modify: `package.json` (script `package`)

**Interfaces:**
- `npm run package` = `vite build && rm -rf dist-zip && web-ext build -s dist -a dist-zip -n metis-weather-$npm_package_version-chrome.zip && web-ext build -s dist -a dist-zip -n metis-weather-$npm_package_version-firefox.zip && git archive --format=zip -o dist-zip/metis-weather-$npm_package_version-source.zip HEAD`
- `ci.yml`: on `pull_request`, and `push` to branches other than `master` (master pushes run the same checks in `release.yml`). Steps: checkout, setup-node (`node-version-file: .nvmrc`, cache npm), `npm ci`, `npm run lint`, `npm test`, `npm run build`, `npm run lint:ext`.
- `release.yml`: on `push` to `master`, `permissions: contents: write`, `concurrency: release`. Same checks, then:

```bash
git config user.name "github-actions[bot]"
git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
v=$(node -p "require('./package.json').version")
if git ls-remote --exit-code --tags origin "refs/tags/$v" >/dev/null; then
  v=$(npm version patch --no-git-tag-version | tr -d v)
  git commit -am "Release v$v"
  git push origin HEAD:master
fi
npm run package
git tag -a "$v" -m "Release v$v" && git push origin "$v"
gh release create "$v" dist-zip/*.zip --title "Release v$v" --generate-notes
```
  (Pushes made with `GITHUB_TOKEN` don't trigger workflows, so the bump commit doesn't loop.)
- `dependabot.yml`: `npm` and `github-actions`, weekly, minor+patch grouped.
