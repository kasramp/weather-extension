# Metis 1.1: Manifest V3, Chrome + Firefox, GitHub Actions

Date: 2026-11-21. Branch: `v1.1`. Status: draft for approval.

## Intent

Metis (this repo) is a weather popup extension built on the Eris API (`weather-api.madadipouya.com`, the user's own service). It last shipped as 1.0.18 (2021), is Manifest V2 only, and no longer loads in current Chrome. Goal: make it work on current Chrome/Chromium **and** Firefox, update the stack, improve the code, replace Travis with GitHub Actions, and end up ready to submit to both stores. Vue stays on purpose: the user wants the project to serve as a Vue example.

Store submission itself is the last step and is planned separately; this design only has to leave everything submission needs in place (packages, docs).

## Goals
- One codebase, one Manifest V3 extension that loads in current Chrome/Chromium and Firefox.
- Vue 3 + Vite, current dependencies, current Node LTS.
- Popup shows weather for the user's location; falls back to IP lookup.
- Smallest permission set: `geolocation` only.
- No remote resources at runtime other than the Eris API.
- GitHub Actions: validate every PR/push; on master, build and publish a GitHub release with zips.
- `publish/` folder: step-by-step guides for Chrome Web Store and Firefox AMO with every form answer written out.
- Version 1.1.0, tags without `v` (like the existing `1.0.x` tags).

## Non-goals
- Fahrenheit/unit setting, options page, forecast, toolbar badge, background refresh.
- Automatic upload to the stores from CI.
- Firefox for Android.

## Anti-goals
- Asking for website/host permissions (the API sends `Access-Control-Allow-Origin: *`, so none are needed).
- Loading fonts/CSS/JS from CDNs (store review friction, leaks user IPs to Google).
- Two separate codebases or manifests to keep in sync by hand.

## Approaches considered

**Location**
- **Chosen: popup asks for location when opened, IP fallback.** The popup is a normal extension page in both browsers and can call `navigator.geolocation`. Same code everywhere, no background script.
- IP on Chrome / geolocation on Firefox: rejected. City-level accuracy, wrong behind a VPN, two code paths.
- Keep background refresh: rejected. Chrome MV3 service workers have no geolocation (would need an offscreen document), Firefox needs an event page; lots of code for weather nobody sees until the popup opens.

**Stack**
- **Chosen (user): Vue 3 + Vite.** Keeps the project a Vue example.
- Plain HTML/JS, no build: rejected by the user.

**Archive**: done. Master as of `d9cf4c9` released as `1.0.19` (archive, MV2, source only).

## Design

### Behaviour
1. Popup opens. If a saved result exists in `localStorage`, render it at once (marked with its fetch time).
2. Call `navigator.geolocation.getCurrentPosition` (timeout ~10 s, `maximumAge` ~10 min).
   - Success → `GET https://weather-api.madadipouya.com/v1/weather/current?lat=..&lon=..`
   - Error/denied/timeout → `GET https://weather-api.madadipouya.com/v1/weather/currentbyip`
3. On success, render and save to `localStorage`. On API failure with a saved result, keep showing it with a small "couldn't refresh" note; with nothing saved, show an error state with a retry button.
4. Loading state while the first fetch runs (today the popup is blank until data arrives).

Location text shown: `name, country` as today. Values shown: same as today (temperature, feels like, min/max, humidity, wind, cloudiness, pressure, visibility). Date/time shown is when the data was fetched (so a saved result is honest), formatted with `toLocaleDateString`/`toLocaleTimeString` (today the time prints as `9 : 5`). API failures come back as HTTP 500 with a non-empty `errors` array; treat both as failure.

### Code layout
```
src/
  manifest.json          single MV3 manifest for both browsers
  popup/index.html
  popup/main.js          createApp(App).mount
  popup/App.vue          view only
  popup/weather.js       fetchWeather(): location → API, IP fallback; plain functions, testable
  popup/icons.js         OpenWeather icon code → { icon class, background colour, image }
  images/, icons/        as today
tests/                   Vitest unit tests for weather.js and icons.js
```
The current mutation of the API object inside `App.vue` is replaced by a small mapping function returning what the view needs.

### Manifest
- `manifest_version: 3`, `action.default_popup`, icons, `permissions: ["geolocation"]`, no `host_permissions`, no background.
- `browser_specific_settings.gecko`: `id` (e.g. `metis-weather@madadipouya.com`, final choice at submission), `strict_min_version` that supports MV3 + `data_collection_permissions`, and `data_collection_permissions.required: ["locationInfo"]` (Firefox requires this declaration for new add-ons). Chrome ignores the key with a warning; acceptable, keeps one manifest.
- `version` filled from `package.json` at build.
- Name shown to users: "Metis Weather" (today it shows `weather-extension`).

### Fonts and styles
- Weather Icons and Raleway bundled from npm packages (`weather-icons` or equivalent, `@fontsource/raleway`), no CDN links.
- `node-sass` dropped; plain CSS or `sass` (Dart Sass) if SCSS stays.

### Tooling
- Node 24 LTS, Vite with a Vue plugin, a small extension-friendly Vite setup (multi-file output: popup HTML, manifest, static assets copied).
- ESLint 9 flat config + `eslint-plugin-vue`, Prettier.
- Vitest for unit tests.
- `web-ext lint` on the built extension (Firefox validator; also catches manifest mistakes).
- Scripts: `dev`, `build`, `lint`, `test`, `package` (produces the three zips below).
- Removed: webpack + loaders, babel, node-sass, release-it, `.travis.yml`, `scripts/build-zip.js` (replaced by `package`).

### Packages (output of `npm run package`, in `dist-zip/`)
- `metis-weather-<version>-chrome.zip` and `...-firefox.zip`: built extension (same contents for now; separate names so the store guides are unambiguous and a browser-specific tweak can land later without changing the docs).
- `metis-weather-<version>-source.zip`: repo source for AMO review (`git archive HEAD`, i.e. all tracked files).

### CI (GitHub Actions)
- `ci.yml` on pull requests and pushes to master (not every branch, to avoid duplicate runs): `npm ci`, lint, test, build, `web-ext lint`.
- `release.yml` on push to master: same checks; if the tag for the `package.json` version already exists, bump patch, commit `Release v<version>` and push it; then `npm run package`, tag and GitHub release "Release v<version>" with the three zips and auto-generated notes. Needs `permissions: contents: write`. *User decision (2026-11-21):* the pipeline bumps the version itself, like the old Travis flow; minor/major bumps are done by editing `package.json` in the PR.
- Dependabot kept, grouped minor/patch updates for npm and actions.

### Docs
- `README.md` rewritten (install from stores/zip, dev setup, release process, screenshot), in the style of the user's wifzf README.
- `publish/`: `CHECKLIST.md`, `chrome-web-store.md`, `firefox-amo.md` (every form answer: description, single-purpose, permission justification for geolocation, data use, privacy policy text/URL, reviewer notes, source-code build instructions for AMO), store listing texts, screenshot/promo image list. Written fully at the submission step; this phase creates the folder skeleton and the package script.
- Privacy policy text (location sent to Eris to look up weather, nothing else stored or shared) to host somewhere public; where is decided at submission.

## Left to the builder
- Exact Vite extension setup (plain Vite config vs a plugin), as long as `dist/` loads unpacked in both browsers and passes `web-ext lint`.
- Exact npm packages for the bundled fonts.
- Styling details, as long as the popup looks like today's (photo background per condition, translucent boxes) and fits the ~360×380 popup.

## Verification
- `npm run lint && npm test && npm run build && npx web-ext lint -s dist` pass.
- `dist/` loads unpacked in current Chromium and Firefox; popup shows weather with location allowed, and via IP with location denied.
- `npm run package` produces the three zips; the release workflow is checked on a fork or by inspecting a dry run before merging to master.
